\begin{abstract}
\noindent C2CAD-Bench v1 was rejected at the NeurIPS 2026 Evaluations \& Datasets track. Reviewers found:
\begin{itemize}
\item the ``zero-scaffolding'' claim was false;
\item the scorer was unvalidated;
\item the isolation of spatial reasoning was asserted rather than shown;
\item the rebuttal's new evidence never reached the paper.
\end{itemize}
This report describes the v2 package that now sits beside the frozen v1 artifact:
\begin{itemize}
\item a re-specified case set, with prompt audits enforced by tests;
\item a scorer that every reference passes at 100, and whose validity is measured before use;
\item reference-free, clause-traced constraints;
\item held-out and scale splits;
\item ten experimental arms that attribute failures to specific sub-skills, including the CAD-code and constrained-decoding conditions promised in the rebuttal;
\item a hardened runner for live API runs;
\item an analysis plan fixed before any data;
\item a one-command analysis pipeline that writes every paper number as a \LaTeX{} macro.
\end{itemize}
The repository is ready for the live runs; no paid request has been made yet.
\end{abstract}

\section{Summary of what changed}
\begin{itemize}
\item \textbf{v1 is frozen; v2 is new.} Nothing in \file{runners/}, \file{data/}, \file{results/} or the reference code in \file{stages/} was modified. All new work lives in \file{v2/}. v1's own tests still pass (11).
\item \textbf{Prompts.} The released v1 prompts leaked totals, formulas and coordinates.
  \begin{itemize}
  \item The v1 audit regexes flag 60 of the 75 v1 prompts and 0 of the 75 v2 prompts (E00).
  \item A test now enforces this as a strict CI gate over the task text of every arm.
  \end{itemize}
\item \textbf{Scorer.}
  \begin{itemize}
  \item One normalizer for both sides, optimal (Hungarian) matching, and a pose gate.
  \item A reference-free semantic layer of 25{,}371 constraints, each tied to a prompt sentence (E09).
  \item No hidden calibration exponent. All 75 references score 100 on every axis, and the scores are invariant to order and ids.

  \item Scale sweep: 121 cases, from 3 to 701 parts.
  \item Held-out: 48 cases with new values, mirrored handedness and rotated anchors. The memorized answer fails every one.
  \end{itemize}
\item \textbf{Ten arms}, each changing one factor: json, neutral, tool, v1, mates, schema, cadquery, probe, repair\_generic and repair\_verifier.
\item \textbf{Live-run machinery:}

\section{Why v2: defects found in v1}
The v1 defects that drove the rebuild:
\begin{itemize}
\item \textbf{Validators contradicted their own references} (E01, \file{v2/experiments/e01_v1_validator_golden_audit.py}).
  \begin{itemize}
  \item In 18 of 25 families, the reference answer scores below 0.999 on its own v1 semantic validator at one or more levels.
  \item Every failing sub-check that could be instrumented is a validator bug. Examples: spacing uniformity computed over paired spheres that share a height; the deck taken to be the longest beam although the cables are longer; tangent contacts counted as interference.
  \item v1 hid this by dividing every model's score by the reference's raw score.
  \end{itemize}
\item \textbf{Released scores and type confusions do not reproduce} (E03, \file{v2/experiments/e03_rescore_v1_outputs.py}).
  \begin{itemize}
  \item Re-scoring the 897 comparable released outputs with v2 gives Spearman $\rho=0.868$ (Kendall $\tau=0.718$) against the v1 model ranking. The top three are unchanged.
  \item The real dominant type substitution is beam$\rightarrow$box: 2{,}049 of 2{,}541 matched pairs, co-located. The paper's ``beam$\rightarrow$sphere 8{,}644'' does not reproduce.
  \end{itemize}
\item \textbf{Scorer bugs} recorded in the lab notebook and the resubmission plan:
  \begin{itemize}
  \item references that do not score 100 against themselves;
  \item order-dependent greedy matching;
  \item a calibration exponent applied to some families only;
  \item unrecognised types passing normalization.
  \end{itemize}
  All are fixed by construction in v2 and guarded by tests. \emph{Their counts come from an earlier, unsaved check and are not quoted here.}
\end{itemize}

\section{The v2 benchmark}
\subsection{Case set and output contract}
\begin{itemize}
\item \textbf{Prompts.} The 75 main cases (25 families $\times$ 3 scale levels) use the rewritten v2 prompts. They carry relations and base values only.
\item \textbf{Output contract.} Each generator's own output suffix is replaced by one shared contract that fixes:
  \begin{itemize}
  \item the field names of the seven primitives (box, cylinder, pipe, cone, sphere, torus, beam);
  \item the unit (millimetres);
  \item the conventions, e.g.\ \texttt{center} is the midpoint of the axial extent, and a cone's axis points from base to tip.
  \end{itemize}
  Neither v1 nor the v2 generator prompts ever stated field names.
\item \textbf{Documented patches.} Deviations from the generators are explicit, documented patches in \file{cases.py}:
  \begin{itemize}
  \item the Suspension Bridge id order and deck section;
  \item the Flanged nut axis;
  \item Axle Bearing: bearings moved outside the block, shaft protrusion 20 (this changes the prompt text);
  \item Honeycomb: the central cell's elevation stated (this changes the prompt text), and the link id order.
  \end{itemize}
  The two prompt changes await the author's sign-off.
\end{itemize}

\section{The v2 scorer}
\begin{itemize}
\item \textbf{Normalizer.} The same normalizer is applied to the reference and to the output. It reads Euler rotations when no axis is given, ignores box rotations (boxes are axis-aligned by schema), and drops out-of-schema types. Each of these actions is counted.
\item \textbf{Coverage} $=100\cdot\min(n,N)/\max(n,N)$. It is symmetric, so missing and excess parts cost alike.
\item \textbf{Geometry.} An optimal one-to-one assignment. A pair scores
  \[ \text{pos}\cdot\text{ori}\cdot\bigl(0.4+0.2\,\text{type}+0.4\,\text{dims}\bigr), \]
  where
  \begin{itemize}
  \item $\text{pos}=\max\!\bigl(0,1-d/(1.5\tau)\bigr)$ with $\tau=\max(2\,\text{mm},\,5\%\text{ of the reference diagonal})$;
  \item $\text{ori}=1-\min(1,\theta/45^\circ)$.
  \end{itemize}
  Type and shape credit therefore count only where the part is placed. Under v1's additive form, randomly placed parts kept 60\% of the credit.
\item \textbf{Geometry-equivalent} additionally scores an axis-aligned beam and a box of equal extents as the same solid. It never lowers a pair's score (a test enforces this).
\item \textbf{Semantic} is the mean over prompt clauses of the fraction of that clause's constraints satisfied.
  \begin{itemize}
  \item Tolerances: length $\max(0.25\,\text{mm}, 0.2\%$ of the diagonal$)$, angle $0.5^\circ$, dimensions 1\% relative.
  \item Roles are bound by the optimal assignment. Binding by the output's own ids is reported separately.
  \end{itemize}
\item \textbf{Global} $=$ mean(Coverage, Geometry, Semantic), with no gates and no calibration. \textbf{Exact} means every constraint is satisfied and the part count is exact. The paper leads with the components and with Exact.
\item \textbf{New in this release:}
  \begin{itemize}
  \item \emph{Label-free prisms} (\file{prism.py}). A rectangular solid built in CAD has no box/beam label and no centerline. The evaluator reads it as the best-fitting of an axis-aligned box or a beam along one of its three axes; the occupied volume is identical for every reading.
  \item \emph{Reference-free verifier} (\texttt{evaluate.verify}). Parts are bound by the output's own ids. It reports the violated prompt sentences with the offending ids, the missing ids and the implied part count, and uses no reference coordinates. It is silent on all 75 references (test).
  \item \emph{OBB orientation error} (\texttt{metrics3d.orientation\_error\_obb}). It is defined for every matched pair whatever the types, so an oriented beam answered by an axis-aligned box counts as the orientation error it is.
  \end{itemize}
\end{itemize}

\noindent What the table shows:
\begin{itemize}
\item \textbf{Relational checks are robust to rigid moves.} Only anchor constraints fail under translation; mates and patterns hold.
\item \textbf{The constraint layer catches sub-millimetre error.} At $\sigma=0.5$\,mm, Geometry barely moves (89.2) while the Semantic pass rate halves (58.3).
\item \textbf{Global has a floor.} Count-only output keeps Global at 36.6 through Coverage, which is why the paper reports components and Exact.
\item \textbf{Decomposition has a measured cost.} Splitting every box costs 5.4 Global points; splitting every beam costs 16.2. The v2 prompts prescribe each part and its id, so a split is a deviation from the specification.
\item \textbf{Rescaling contradicts the rebuttal.} The rebuttal (under v1) reported that Semantic stays near 99 for rescaled answers. Under v2 it falls to about 60, because every v2 prompt states its dimensions, so a rescaled answer really is wrong. Only relational kinds hold (orientation 88\%, topology 100\% at $\times1.5$). The rebuttal's sentence must not be reused.
\end{itemize}

\subsection{Sensitivity, convergent validity and cross-implementation}
\begin{itemize}
\item \textbf{E04, 20 scorer variants.} They vary:
  \begin{itemize}
  \item the pair form and the coverage form;
  \item the position tolerance and the orientation saturation;
  \item the constraint tolerances ($\times0.5$ to $\times5$);
  \item six weightings, including Geometry-only and Semantic-only;
  \item all v1-like choices at once;
  \item three groupings of constraints into Semantic.
  \end{itemize}
  The top-three set is the same in all 20. The lowest agreement with the default ranking is Spearman $\rho=0.940$ (Kendall $\tau\geq0.795$).
\item \textbf{E05, against standard shape metrics} (897 released outputs).
  \begin{itemize}
  \item Case level: Geometry agrees with IoU at $\rho=0.807$, with F-score at 2\% at 0.816, and with Chamfer at 0.753. Semantic agrees with IoU at 0.823. Coverage agrees with IoU at only 0.484: volume metrics are nearly blind to the part count.
  \item Model level (against Global): IoU 0.896, F@2\% 0.951, Chamfer 0.918.
  \item Disagreement quadrants: 31.7\% (284/897) have F@2\%$\,\geq0.9$ yet are not exact; 6.0\% have IoU$\,\geq0.8$ with Sem$\,<60$; 2.3\% have IoU$\,<0.3$ with Geom$\,\geq80$.
  \item Caveat: the released v1 records were stored after v1's parsing. The live runs re-establish these cases on v2 outputs (a05).
  \end{itemize}
\item \textbf{E07, an independently written matcher} (June 2026).
  \begin{itemize}
  \item Like for like, it reproduces the model Geometry ranking exactly (Spearman 1.000). At case level the agreement is $\rho=0.988$, with 89.9\% of cases within 2 points.
  \item The comparison also exposed two v2 normalizer gaps (beams without a section; Euler angles under \texttt{orientation}). Both are fixed and tested.
  \end{itemize}
\item \textbf{E08, CAD-kernel round trip} (\file{v2/experiments/e08_kernel_roundtrip.py}).
  \begin{itemize}
  \item All 5{,}042 reference primitives build as valid OpenCascade solids, and all 5{,}042 are recovered from their B-Rep faces (2{,}502 of them as label-free prisms).
  \item Through the complete cadquery-arm path (program $\rightarrow$ sandbox $\rightarrow$ kernel $\rightarrow$ recovery $\rightarrow$ evaluator), 75/75 cases are exact. The lowest Geometry is 99.999998, which is rounding.
  \end{itemize}
\end{itemize}

\subsection{Hypotheses fixed before the runs}
Effects are arm minus json on the expected single-attempt exact rate:
\begin{itemize}
\item per case, averaged over cases;
\item with 95\% CIs from a family-cluster bootstrap and family-level sign-flip $p$-values (Holm-corrected);
\item pooled over models with the same family draw.
\end{itemize}
Verdicts are three-valued: \emph{supported}, \emph{contradicted} or \emph{inconclusive}. For the equivalence hypotheses the margin is $\pm5$ percentage points.
\begin{table}[h]\small
\begin{tabularx}{\linewidth}{@{}lLL@{}}
\toprule
& contrast & reading if supported \\ \midrule
H1 & tool $>$ json and mates $>$ json & computing and writing numbers is a bottleneck \\
H2 & mates $>$ tool (16 gated vs.\ 9 ungated families) & a relational interface helps beyond arithmetic \\
H3 & neutral $\approx$ json & recall of named objects does not drive scores \\
H4 & v1 $>$ json, per family & how much the released prompts helped \\
H5 & schema $\approx$ json & the output format is not the bottleneck \\
H6 & cadquery vs.\ json; rate of ``builds but wrong'' & build success does not imply spatial correctness \\
H7 & probe $>$ the same parts in full answers & serialisation / length cost \\
H8 & repair\_verifier $>$ repair\_generic at round $R$ (plus oracle single-channel bounds) & constraint feedback repairs answers \\
\bottomrule
\end{tabularx}
\end{table}

\noindent Also pre-registered:
\begin{itemize}
\item model \emph{tiers} (Holm-corrected pairwise tests), not ranks, and the variance decomposition (model, family, interaction);
\item \emph{breaking size} on the sweep: a logistic fit in $\log_2$(parts) with penalised family offsets, where infeasible and truncated responses are censored, and no extrapolation is made beyond the observed sizes;
\item the \emph{held-out minus main} gap, with a memorization index: the share of held-out answers closer to the default answer;
\item \emph{validity on live outputs}: the metrics of E05, the kernel build rate of json answers, a failure taxonomy, and a list of never-solved cases for the prompt-sufficiency review.
\end{itemize}

\section{Run infrastructure}
\begin{itemize}
\item \textbf{Providers.}
  \begin{itemize}
  \item Supported: OpenAI, Anthropic (official SDK), Google, DeepSeek, Moonshot, OpenRouter and Together.
  \item Every request is streamed.
  \item Transient errors (408/409/425/429/5xx/529, timeouts) are retried with exponential backoff that honours \texttt{retry-after}; other client errors are not retried.
  \end{itemize}
\item \textbf{Records.} Every request is appended to \file{runs/<run>/responses.jsonl} before scoring. It records:
  \begin{itemize}
  \item the settings actually sent, including whether the temperature was sent;
  \item the returned model version, finish reason, usage and cost;
  \item latency, attempts, schema enforcement and the repair feedback text;
  \item the raw answer.
  \end{itemize}
  Scores go to \file{scores.jsonl}. The manifest holds the git commit, the code and case-file hashes, the registry entries and the argv.
\item \textbf{Resume and budget.}
  \begin{itemize}
  \item A completed or infeasible request is never bought twice; API errors are retried on the next invocation.
  \item \texttt{--max-usd} caps the listed profiles' recorded spend.
  \item \emph{Infeasible} means that the answer alone cannot fit the model's output cap. Such cases are excluded, never counted as failures.
  \end{itemize}
\item \textbf{Safety of the records.} A scoring crash is recorded as a harness error and loses nothing. Appends are file-locked, so several processes can write to one run directory. \texttt{python -m c2cad.runner.rescore} re-scores every recorded answer offline.
\item \textbf{Smoke gate.} \texttt{--smoke} runs the smallest and largest feasible case per arm. It checks the finish reason, usage, returned model, parsing and truncation, and must print \texttt{SMOKE PASSED} before a full run.
\item \textbf{Sandboxes.} Model programs run in a separate interpreter under:
  \begin{itemize}
  \item an AST allow-list;
  \item an empty temporary directory;
  \item \texttt{RLIMIT\_FSIZE}$\,=0$;
  \item CPU and wall-clock limits.
  \end{itemize}
  CadQuery programs run in the CAD environment (\file{v2/.venv-cad}, CadQuery 2.8) with file export banned.
\end{itemize}

\section{Analysis pipeline}
One command, \texttt{cd v2 \&\& python -m analysis.make\_all}, reads every real run directory and writes the following to \file{v2/reports/results/analysis/}:
\begin{itemize}
\item \textbf{a01}: outcomes per model $\times$ arm (first attempt, mean over $k$, pass@$k$, all axes with cluster CIs); response statuses; cost and returned versions; tiers; variance decomposition.
\item \textbf{a02}: attribution contrasts and verdicts H1--H7; per family and per constraint kind; mates gated vs.\ ungated with the invalid-program rate; cadquery runs, builds and ``builds but wrong''; probe vs.\ full answer.
\item \textbf{a03}: breaking size (censored) with largest scale solved per family; held-out gap; memorization index.
\item \textbf{a04}: repair trajectories by round, the H8 verdict, and oracle single-channel repair bounds (types, positions, missing parts) on the same seeds.
\item \textbf{a05}: validity on live outputs (IoU, Chamfer, F-score, axis and OBB orientation); disagreement quadrants with examples; per-case metrics CSV; kernel build of json answers; failure taxonomy; co-located type confusions; the prompt-sufficiency review list.
\item \textbf{a06} and figures: annotated failure renders (parts coloured as correct, misplaced, substituted, extra or missing), the attribution forest plot, the family $\times$ arm heat map, scale curves and repair curves.
\item \file{paper_numbers.tex}: every quoted number as a \LaTeX{} macro, so the paper text cannot drift from the data.
\end{itemize}
The pipeline was exercised end to end on about 8{,}300 records from three mock models over every arm and split. These are tests of the machinery, not results.

\section{How to run}
\begin{small}
\begin{verbatim}
cp v2/.env.example v2/.env          # fill in only the providers you will run
cd v2
python -m c2cad.runner.run --profile gpt-6-sol --arms json,neutral,tool,v1,mates,schema,\
    cadquery,probe,repair_generic,repair_verifier --smoke --run smoke_gpt-6-sol
python -m c2cad.runner.run --profile gpt-6-sol --arms json,neutral,tool,v1,mates,schema,\
    cadquery,probe --k 3 --run main --workers 6 --max-usd 400
python -m c2cad.runner.run --profile gpt-6-sol --arms repair_generic,repair_verifier \
    --run main --workers 6 --max-usd 450
python -m c2cad.runner.run --profile gpt-6-sol --split sweep --arms json,tool,mates --k 1 \
    --run sweep --max-usd 100
python -m c2cad.runner.run --profile gpt-6-sol --split heldout --arms json,tool,mates --k 3 \
    --run heldout --max-usd 100
python -m analysis.make_all
\end{verbatim}
\end{small}

\section{Open decisions and limitations}
\begin{itemize}
\item \textbf{Before the first paid request}, because these change what models receive:
  \begin{itemize}
  \item sign-off on the two prompt patches and on the output contract;
  \item the model roster and the reasoning setting per profile;
  \item the budget;
  \item confirmation of the four unverified registry entries.
  \end{itemize}
\item \textbf{Axle Bearing} has 5 parts at every level. Describe its levels as parameter variants, or redesign the family.
\item \textbf{Decomposition merge pass} (promised to Reviewer 3): not implemented; E02 measures the cost of splitting instead.
\item \textbf{Not yet done:}
  \begin{itemize}
  \item CML gate programs for the remaining 9 families (the expressibility map currently covers 16/25);
  \item the human rating study;
  \item an independent audit of the trace map;
  \item a hand review of the high-overlap prompts;
  \item OpenSCAD, which is not installed and has no arm.
  \end{itemize}
\item \textbf{Scope.} Primitive assemblies only: no B-Rep editing and no feature trees. API models drift, so the returned versions and dates are recorded per request.
\end{itemize}
